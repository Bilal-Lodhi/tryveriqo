# Release notes — tryveriqo v0.1.0

**Status: published as a pre-release.** The source is public in
`Bilal-Lodhi/tryveriqo`, continuous integration is green on `main`, and `v0.1.0`
is tagged and published as a **pre-release**:

<https://github.com/Bilal-Lodhi/tryveriqo/releases/tag/v0.1.0>

No package was published, no container image was pushed to a registry, and there
is **no hosted instance**. The tag is immutable and points at the release commit;
the post-release documentation lives on `main` and does not move it.

## What this is

The first release candidate of **tryveriqo**: an open-source, self-hostable
service for generating online assessments and giving reviewers evidence-based
integrity signals about how candidates completed them.

## Highlights

* **Assessment generation** from a single description, producing a structured
  suite with roles, competencies, problems, hidden test cases, scoring formulas
  and per-problem integrity thresholds.
* **Candidate sessions** with short-lived, candidate-scoped credentials and a
  full lifecycle (`in_progress → submitted → flagged → evaluated`, or
  `terminated`).
* **Telemetry ingestion** for nine event types, with duplicate suppression and
  post-restart recovery.
* **Integrity analysis** producing an advisory score, structured flags, a
  similarity report and behavioural anomalies — deliberately described as
  signals, never as findings.
* **A reviewer console** with the submission beside the candidate's timeline.
* **Security by default**: fail-closed production startup, no default credential,
  an explicit CORS allow-list, and a token-guarded tool surface.
* **A self-hostable stack**: `cp .env.example .env && docker compose up --build`.

## Defects found and fixed during live verification

Both were invisible to the fixture-based suite and were found only by exercising
the real provider and the real container.

1. **Every generated suite collided on one `suiteId`.** Asked for a unique UUID,
   `gemini-2.5-flash` returns the same memorised placeholder on every call. The
   unique index on `metadata.suiteId` then rejected the second suite, which was
   lost while the API still reported success to the caller. Fixed in the parser
   (placeholder ids are replaced; genuine model ids stay authoritative) and in the
   store (idempotent upsert on `suiteId`). Regression tests added at both layers.
2. **Container supervision never noticed the tool transport dying.** The
   entrypoint used `wait -n`, which under BusyBox `ash` does not return when a
   tracked child dies after it has started blocking. Replaced with explicit
   liveness polling; verified by killing the transport in a running container.

A third defect was in the verification scripting, not the product: `npm run
verify` asserted a session status that only holds without an AI credential. The
assertion was corrected without weakening any product behaviour.

## Known gaps

These are deliberate v0.1.0 boundaries, documented rather than hidden.

1. **Vertex AI transport is not live-verified.** It is implemented and covered by
   request-construction tests, but no Google Cloud project or ADC was available.
   Only `gemini-api` is exercised end to end.
2. **The console's operator token is compiled into the web bundle.** Confirmed by
   building with a sentinel token and finding it verbatim in `main.dart.js`. Safe
   for a local/trusted console or a proxy that injects the credential server-side;
   never for a publicly served static build with a production token.
3. **Candidate registration is open.** Any caller may register any `candidateId`
   and receives a token scoped to exactly that id, with no check that the id is
   unused. Cross-candidate *writes* are refused with `403`: a batch may name only
   one candidate, must match the token, and must own the target session. What
   remains is a read exposure — a token for a known candidate id can read that
   candidate's own reviews, submitted code and reports — so a deployment with
   untrusted candidates must close this at the edge. Tracked as issue #2.
4. **Integrity output is advisory.** No output proves misconduct.
5. **Reference completions for similarity analysis are supplied by the caller.**
   There is no external corpus, so this is not yet a plagiarism check against the
   open web.
6. **Single shared operator credential.** No per-reviewer identity, no RBAC, no
   access log.
7. **No live session streaming.** The API is request/response and the console
   refreshes on demand.
8. **No provider abstraction beyond the single Gemini implementation.** The
   boundary exists; a second provider has deliberately not been added.
